## 1. kiwi_generator cannot be installed alongside modern codegen

`dart pub outdated` in `packages/kiwi_generator`:

```
analyzer      6.4.1   → resolvable 10.2.0 → latest 14.1.0
source_gen    1.5.0   → resolvable  4.2.4 → latest  4.2.4
build         2.4.1   → resolvable  4.0.7 → latest   4.0.9
dart_style    2.3.6   → resolvable  3.1.5 → latest  3.1.12
build_resolvers    2.4.2  (discontinued)
build_runner_core  7.3.2  (discontinued)
```

Any user with `freezed` or `json_serializable` at current versions hits a
version-solve failure. This is almost certainly what issue **#91 ("It is not
generating anything")** is, and it is why **PR #126** (dart_style 3.0.1, open
since Jan 2025) has been stuck — dart_style 3 requires
`DartFormatter(languageVersion:)`, and `kiwi_injector_generator.dart:45` calls
the bare `DartFormatter()`.

**Migration surface** (the generator is only 236 lines, mostly mechanical):
- element model: `ClassElement` / `MethodElement` / `.parameters` — reworked in analyzer 7+
- `getDisplayString(withNullability: …)` — the parameter was removed
- `TypeChecker.fromRuntime` → `TypeChecker.typeNamed` (source_gen 2+)
- `DartFormatter()` → `DartFormatter(languageVersion: …)`

**Consequence to accept up front:** the SDK floor moves from `>=2.14.0` to
`^3.5.0`+. That is a major bump — kiwi_generator 5.0.0. Say it in the changelog,
don't hide it.

## 2. CI structurally cannot catch #1

Both examples declare:

```yaml
dependency_overrides:
  kiwi:           { path: ../../packages/kiwi/ }
  kiwi_generator: { path: ../../packages/kiwi_generator/ }
```

The overrides mask resolution exactly where a user would hit it. So the badges
stayed green for 19 months while the published package was un-installable.
**This is the root cause of the rot, not neglect.**

Fix: add a job that creates a throwaway app depending on published/path kiwi
*without* overrides, plus `json_serializable`, and runs `dart pub get`.

## 3. The codegen-drift gate in `build_all.yml` has never fired

```yaml
- name: Use verify-changed-files ...
  uses: tj-actions/verify-changed-files@v20      # ← no `id:`
- name: Run step only when ...
  if: steps.verify-changed-files.outputs.files_changed == 'true'
  run: echo "..."                                 # ← only echoes, never fails
```

No `id:` → the `if:` is always false. And even if it fired it echoes instead of
exiting non-zero. Two-line fix: add `id: verify-changed-files`, and `exit 1`.

## 4. Other CI / tooling gaps

- Examples run only `flutter analyze` — no `dart test`, and `tools/test.sh`
  literally prints `"No tests for dart_kiwi"`.
- No coverage measurement anywhere.
- `dependabot.yml` covers both packages **and** root `github-actions` (correct).
  It does not cover `/examples/*` or `/tools/kiwi_cli_actions` — minor.
- Lint config is 6 hand-picked rules. No `package:lints/recommended.yaml`.
  That is why nobody caught finding #5.
- **`tools/*.sh` are all committed without the executable bit.** `./tools/all.sh`
  dies with "Permission denied", and even via `bash` it calls `./packages_get.sh`
  with no cd-guard (unlike its siblings), so it only resolves from inside
  `tools/`. The whole helper suite is effectively dead. `chmod +x` + a cd-guard
  in `all.sh` is a 5-minute fix.
- **`packages/*/mono_pkg.yaml` are dead config** — dart-lang `mono_repo` stanzas
  invoking `dartfmt` and `dartanalyzer`, both long removed from the SDK. Nothing
  reads them. Delete.

## 5. `import 'package:build/src/builder/build_step.dart'` — VERIFIED removable

`kiwi_injector_generator.dart:5` reaches into another package's `src/`.
`BuildStep` is already exported by `package:build/build.dart` on line 4.

Deleted it locally → `dart analyze --fatal-warnings` clean, all 10 tests pass.
One-line delete. `implementation_imports` (in `package:lints/recommended`)
would have flagged it.

## 6. `silent` mode: docs promise something the code doesn't do

`packages/kiwi/README.md`: *"In production, or when `silent` is `true`, you will
get `null` if you try to resolve a type that was not previously registered."*

`kiwi_container.dart:156` respects `silent`. But `:162-165` throws
`NotRegisteredKiwiError` **unconditionally**. And `T resolve<T>()` returns
non-nullable `T`, so it *cannot* return null for a non-nullable type. The
"Silent=true" test group only covers happy paths — nothing asserts this.

Not a patch — an API decision:
- (a) fix the README to describe what actually happens, or
- (b) add `T? resolveOrNull<T>({String? name})` and point `silent` at it.

(a) is the honest 20-minute fix. (b) is a 6.0.0 conversation.

## 7. `providers` getter leaks the live internal map

`kiwi_container.dart:51` returns `_providers` by reference — a caller can mutate
container internals. `namedProviders` / `unnamedProviders` at least copy.
Real encapsulation hole, but it's shipped public API on 5.0.1 with 348 stars.
**File under 6.0.0 candidate, not "fix now."**

## 8. Smaller code notes (backlog, not blockers)

- The same ~5-line error string is duplicated **four times** in `resolve` /
  `unregister` / `resolveAs`. Extract one private builder.
- `resolveAs` is `@visibleForTesting` yet is part of the public surface — odd contract.
- `_Provider.get`: a singleton whose builder returns `null` sets `_oneTime = false`
  and then re-invokes the builder on every resolve. Edge case, but it silently
  stops being a singleton.
- Generator strips nullability (`withNullability: false`), so `Foo? foo` emits
  `c.resolve<Foo>()`. Fine when the user registered `Foo`; breaks only if they
  registered `Foo?` as a distinct key. Minor on its own — its real weight is that
  the flag was removed in analyzer 7, so it's a migration item.
- No `dispose`/`onUnregister` hook; `unregister`/`clear` drop instances without
  letting them clean up. Frequently-requested DI feature, worth a ticket.
